# 4. Optional OAuth per instance, API token as the default path (D4)

Status: Accepted

## Context

Not every provider offers OAuth, and OAuth apps are registered per operator. A central sign-in service run by the project would make every instance depend on it.

## Decision

Adapters declare which sign-in methods they support. OAuth 2.0 with PKCE is offered when the instance has an OAuth client for the provider: configured by the operator through environment variables, or registered automatically where the provider supports dynamic client registration (RFC 7591). Otherwise the user follows a guided token setup that links to the provider's token page and lists the exact permissions. Own servers use SSH keys generated by Lotse. Adapters only ever receive finished credentials; where the client comes from is invisible to them.

## Consequences

Works without any service of the project. A central OAuth broker can be added later as one more client source without changing adapters (see ADR 0017).
